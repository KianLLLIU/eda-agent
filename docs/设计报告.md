## 一、需求分析

### 1.1 题目要求

本作业要求实现一个「会画板子的 AI」：用户输入一句自然语言（如「帮我设计一块 Arduino
最小系统板」），Agent 自动产出 **BOM 元器件清单、网表连接、KiCad 可打开的原理图**。

基础任务（40 分）为五步闭环：

1. 环境搭建（Python 3.10+ / KiCad 8）
2. 自然语言 → BOM
3. 电路连接关系生成（结构化 JSON）
4. 导入 KiCad 生成原理图
5. 简单交互修正

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| 可落地 | 助教按 README 5 分钟跑通，输入需求即可出图 |
| 可解释 | 关键设计决策（选型、连接、Prompt）能口头讲清 |
| 可扩展 | 符号库、模板、LLM 供应商均易扩展 |
| 离线可用 | 无 LLM API 也能跑通（内置模板兜底） |

### 1.3 技术选型对比

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| SKiDL（Python 网表库） | 电路即代码，成熟 | 生成 KiCad 8 原理图受限，依赖 KiCad 符号库 | 参考其思想 |
| 复用第三方生成脚本 | 省力 | 黑箱，答辩难解释；格式耦合 | 弃用 |
| **自研 JSON→kicad_sch 生成器** | 吃透格式、可控、可解释 | 需理解 s-expression | ✅ 采用 |

### 2.3 双模式设计（关键设计决策）

- **LLM 模式**：配置 API Key 后，调用大模型生成设计 JSON，Prompt 中注入符号目录约束选型。
- **离线模板模式**：无 Key 时按关键词匹配内置模板（Arduino 最小系统、LED 指示灯、LDO 稳压），
  **保证在任何环境都能演示完整流水线**。
- **自动降级**：LLM 调用失败时自动降级到模板，不中断用户体验。

## 三、Prompt 设计思路

这是本项目的核心。LLM 的输出不可直接信任，因此 Prompt 从三个层面做约束：

### 3.1 符号目录约束（防幻觉）

在 Prompt 中**显式列出可用符号及其引脚编号**，要求模型只能在此表内选型、只能用表中
引脚号连接。例如：

```
可用符号表（只能使用这些符号，引脚号必须匹配）：
- Device:R（引脚: 1, 2）
- MCU_Microchip_ATmega:ATmega328P（引脚: 1=PC6/RESET, 7=VCC, 8=GND, ...）
- ...
```

这样从源头杜绝「编造一个不存在的器件」或「连一个不存在的引脚」。

### 3.2 结构化 JSON 约束

用 `response_format={"type":"json_object"}` 强制 JSON 输出，并在 Prompt 中给出完整
schema 与字段说明（groups/components/nets），保证下游生成器能直接消费。

### 3.3 Few-shot 示例锚定

给出一个最小完整示例（LED + 电阻），锚定输出结构、命名规范（大写网络名、ref 唯一），
稳定模型输出格式。

### 3.4 工程化兜底

即使 Prompt 完美，模型仍可能出错。因此加一层 `validator.py`：
- 元件编号唯一性检查
- 符号存在性检查（查符号库）
- 引脚号合法性检查（查符号定义）
- 网络去重、未分组元件自动归类

非法输出直接抛错反馈，而非静默产出错误电路。

## 四、KiCad 原理图生成

### 4.1 技术要点

生成器直接写出 KiCad 的 s-expression 格式 `.kicad_sch`，关键约束（经实测验证）：

1. **网络标签连接、零导线**：每个引脚旁放同名 net label，同名即相连，避免画导线的高错误率。
2. **power 符号不实例化**：KiCad 10 中 `power_in` 引脚需物理导线才能建网，故电源网络
   统一用 label 表达。
3. **1.27mm 网格对齐**：所有坐标对齐到 50mil，否则 ERC 报 `off connection grid`。
4. **符号局部 y 轴翻转**：符号定义 y 向上、原理图 y 向下，计算引脚世界坐标须翻转 y。
5. **lib_symbols 内嵌**：符号定义完整写入原理图，打开即用，不依赖外部库。

### 4.2 模块化布局

按功能模块（电源/主控/信号/接口）分区摆放，模块间画虚线边框 + 模块名，元件按符号
实际尺寸排列不重叠，产出整洁可读的原理图。

## 六、失败案例与反思

### 6.1 符号坐标系翻转

**现象**：早期尝试沿用「数学 y 向上」坐标矩阵计算旋转元件引脚世界坐标，导致 pin1/pin2
左右对调、网表连错引脚。

**解决**：明确 KiCad 符号局部 y 向上、原理图 y 向下，计算时先翻转局部 y；并进一步简化——
所有符号统一水平定义、rotation=0，从根上规避旋转矩阵出错的可能。

### 6.2 中文工程名兼容性

**现象**：生成的文件名含中文（如「LED 闪烁电路」），担心跨平台/KiCad 兼容问题。

**解决**：工程文件名统一 ASCII（`_slugify` 去除非 ASCII），标题保留在文件内部
`PROJECT_NAME` 文本变量与报告中。

### 6.3 LLM 输出不可信

**现象**：模型偶尔返回缺字段、编造引脚、格式包裹在 markdown 代码块里的 JSON。

**解决**：`extract_json` 稳健解析 + `validator.py` 兜底校验 + 失败自动降级模板。
