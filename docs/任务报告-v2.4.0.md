## 一、任务背景与目标

用户反馈三个阶段的痛点，逐轮澄清后确定的目标：

1. **板子库单一**：网页端只能生成 LED 灯板 → 扩充板子类型
2. **绘图质量不足**：元件排布、走线、复杂电路、KiCad 实时绘图都有欠缺 → 引入开源方案重构
3. **智能化不足**：需要对话实时驱动 + 布线自动化 + 布线后自检/通电模拟/自动修正 + 可自行切换大模型 API

最终架构：**Hy4 flash 对话生成设计 → Agent 智能摆件 → Freerouting 自动布线 → 自检/通电模拟/自动修正 → KiCad 打开验证**。

## 五、关键技术决策与踩坑

1. **Freerouting v2.5 原生 CLI 有 GraalVM bug**：布线到保存阶段崩溃（`SerializationConstructorAccessor class not found`），改用 jar + Java 25（class 69，Java 21 不够）。
2. **Download 慢**：GitHub Releases 直连约 300KB/s，改用 ghfast.top / ghproxy.net 镜像后 16 秒下完 64MB；Java 25 用清华 Adoptium 镜像。
3. **Specctra DSN 坐标/旋转**：官方 fixtures 里 1 unit = 1µm；KiCad rot=90 的焊盘变换与 Freerouting 不一致，最终用「每实例独立 image + 旋转烘焙进 pin 坐标 + place rot=0」解决。焊盘障碍放大 0.6mm、clearance 250、线宽 clamp ≥ 0.2mm，DRC 才归零。
4. **SES 格式**：网络名在外层 `(net GND (wire (path B.Cu 2500 x y ...)))`，坐标 1 unit = 0.1µm。
5. **无网络焊盘**：必须给 `unconnected-` 前缀独立网络，否则走线压上去造成短路。
6. **通电模拟判据**：不能只从连接器 BFS（J1 常未接线会误判），改成最大连通分量 ≥ 已接线元件。
7. **IC 供电检查**：不要猜引脚号（AVR 7/8、555 是 1/8），改成「任意引脚接到电源/地网络即通过」。
8. **自动修正**：Issue 携带结构化 data 字段，不靠正则解析中文消息。
9. **kicad-cli  vs kicad.exe**：ERC/DRC 必须用 kicad-cli.exe，用 GUI 版会超时。

## 六、已知限制与后续建议

| 项 | 说明 |
|---|---|
| 通电模拟 | 是**静态电气推理**，不是 SPICE 瞬态仿真；不验证信号时序、电源完整性、EMC。上电前仍需万用表确认电压极性 |
| Freerouting | 对密集多层板布通率有限（官方基准约 75% 板可完全布通），复杂板可能残留飞线，需人工补布 |
| KiCad IPC | 需用户在 KiCad `Preferences → Plugins → Enable IPC API Server` 开启并重启；未开启时自动降级为「文件生成 + 打开工程」 |
| 安装包体积 | v2.3/v2.4 安装包 118MB（内置 Java25 + Freerouting）；便携版 23MB，但便携版需本机已有 Java 才能自动布线 |
| 自动修正范围 | 目前修正引脚短路与 DRC 间距；拓扑级设计错误（如电源接反）仍会如实报告，不强行"修"（避免掩盖设计意图错误） |

**后续可考虑**：
- 接入 SPICE 仿真做真正的模拟电路通电验证（需要 ngspice + 模型库）
- 把 Freerouting 换成 IPC 模式直连 KiCad（v2.5 已支持），省去 DSN/SES 往返
- 为高层板增加「关键网络手工预布 + 锁定」工作流
